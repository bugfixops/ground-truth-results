### Harness finding (verified by me on all 26 runs, 2026-10-24)
- `merged.ec` is exactly the union of coverage segments 1..N in every app and tool. Segment `00000.ec` (the launch dump, taken just before the tool starts) is never included.
- For Monkey, segment 00000 has probes that never appear later in 9 of 13 apps (AnyMemo 133 probes in 11 classes, Vanilla-Music 181 in 10 incl. MediaScanner/MediaLibrary, MMEX 335 in 46 (many library classes), LibreTorrent 112 in 24, Omni-Notes 45 (SqlParser, DbHelper), hash-checker 38, AmazeFileManager 29 (UtilsHandler, TabHandler), Markor 14, Aegis 4). For APE the gap is 0 to 3 probes. Currency, Diary, openlauncher, AnkiDroid: no gap.
- So first-launch code (DB creation, initial media scan, first-run settings) counts as "missed by Monkey" although it ran. The Omni-Notes and Amaze maps' INFERRED claim "Monkey started with existing data" is most likely this artifact instead.
- Unparsable (failed) dumps: AnkiDroid monkey 3, hash-checker 1 each tool, Omni-Notes ape 1. The hash-checker map also reports coverage lost on process death (dumps reset every 30 s).
- Graphs are unaffected (a hit is still a hit). Per-app READMEs should flag launch-time candidate targets. Tell Yang (target selection T = R minus M).
- Code that runs in a separate process is invisible to the baseline: the coverage receiver dumps only the main process (LibreTorrent `ErrorReportActivity` in `:acra`). Its 0 hits are not evidence; flag such methods in READMEs.
- Sent the tooling run (design-revise step) an extra requirement: collapse call chains through excluded Dagger/Hilt generated code so @Provides methods, @Inject constructors and injected members keep incoming edges.

### Decisions to carry into Phase 2
- Environment needs (server, root, plugin app, hardware, system UI outside the package, fixture files) go in `env` with a consistent category prefix, so the paper can filter targets that need setup. Agree the exact tags with the tooling output before launching.
- Generated code that JaCoCo reports (Glide in Amaze, data binding in LibreTorrent, ButterKnife `_ViewBinding` in Omni-Notes) must be tagged so it does not swamp the DEAD or target counts.
- Screens in other packages (system document picker, camera, share chooser, browser) are real pages for a user. Model them as external pages with RESULT edges and an `env` tag that names the package (e.g. "outside package: com.android.documentsui"), so the methods stay REACHABLE and the paper can see which targets need a tool that may leave the app. Same for setup gates reached through them (MMEX database, Aegis import, hash-checker file pick).
- Classes that are not instrumented (Aegis `RootShellTask`, `RawSlot`) and code in other processes (LibreTorrent `:acra`, AnyMemo `:remote` alarm receiver) are "not observable": say so in the CSV note and README instead of treating 0 hits as evidence.
