What was reviewed by hand (class level, from the method names, the manifest, the layouts and the fixtures on the baseline device):

- **Fixtures.** The baseline device held 12 mp3 and 3 wav files in `/sdcard/Music` (`final_java_only/_fixtures`). The tag parsers `OpusFile`, `OggFile`, `FlacFile`, `Mp4File` can therefore never run on the baseline, and their incoming call edges carry `needs_state` ("the media library holds an audio file in this format"). Playlist export / import (`PlaylistObserver.asM3u`, `fromM3u`, `importM3uPlaylist`, ...) carries `needs_state` ("a playlist exists").
- **Widgets.** `FourLongWidget`, `FourSquareWidget`, `FourWhiteWidget`, `OneCellWidget`, `WidgetD`, `WidgetE` are `AppWidgetProvider`s declared in the manifest. The system creates them when the user adds a widget on the launcher, so their callbacks hang below the pseudo page `S_SYS_<Class>`, entered from `S_ENTRY` through an `env` edge. Vanilla's own code only calls their static helpers (`checkEnabled`, `updateWidget`).
- **Permission screen.** `PermissionRequestActivity` is only shown when a runtime permission is missing; the baseline emulators had permissions pre-granted, so the edges into it carry an `env` gate (edges into methods the baseline did run lose the gate automatically).
- **Drag-sort list** (`DragSortListView`, `DragSortController`, `DragSortTracker`; used by the queue, playlists, tab order and folder picker): its touch callbacks are gated by "the list shows at least one row", so the drag internals show as after-setup.
- **Pager adapters** (`LibraryPagerAdapter`) are not row-gated: the library tabs exist without user data. Cursor / list adapters (`MediaAdapter`, `PlaylistAdapter`, ...) are.
- **Dead code** is mostly unused library code (`SimpleDragSortCursorAdapter`, `DragSortCursorAdapter`, `ResourceDragSortCursorAdapter`, `DragSortListView$LiftAnimator`), unused constructors of static-only helper classes (`PrefKeys`, `PrefDefaults`, `FileUtils`, `MediaUtils`, `SystemUtils`, `PluginUtils`, ...) and a handful of unused methods (`SongTimeline.reshuffleTimeline`, `FancyMenu.add(int,int,int,CharSequence)`, `ThemeHelper.usesDarkTheme`).
- **Handler messages.** `PlaybackService`, `MediaScanner`, the activities and other handlers receive their messages from the send sites of their own class family (`INFERRED`); handlers without such a site fall back to every send site.
