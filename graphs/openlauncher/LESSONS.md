# openlauncher: what reading the routes and citations found

- **A guard and its ENV gate can be written backwards for the same reason an early return hides a guard.** `DialogUtils$9.onSelection -> DialogUtils.copy` carried `env=ENV_STORAGE_FAIL` ("a backup or restore step throws") while its own `guard` said the opposite ("do not throw"). The fix came from reading the *whole* method, not just the cited lines: `System.exit(1)` for Restore sits **after** the try/catch, not inside either branch, so it runs whether or not `copy()` threw - a detail that is invisible if you only read the lines a citation points at and trust the guard text next to it without checking it against the control flow one more time.
- **The established "failure-mode" ENV convention in this same file (`ENV_OLD`, `ENV_WALLPAPER`, `ENV_STARTFAIL` - all paired with a guard like "the try block threw") is a good cross-check for a *new* ENV/guard pair**: when a new gate's text says "X throws" but its guard says "X does not throw" (or vice versa), one of the two is wrong before you even open the source file.
- **Downloaded AOSP framework source is reusable across apps on the same tag.** All 28 distinct `FW-SRC` framework files cited by this app (`ActivityThread`, `View`, `Parcel`, `AlarmManagerService`, `WindowManagerService`/`DragState`, etc.) were already present under `work/fw_src/android-8.1.0_r1/` from earlier apps' sessions; none had to be re-downloaded. Checking ~60 distinct cited line-range groups against them found zero wrong citations in this app - the earlier session that wrote these claims already read the real source carefully the first time, so a careful first pass saves a later verification pass real work.
- **A tool can silently mis-parse its own house style.** `tools/show_route.py`'s citation-extraction regex (`[^\s;]+`) assumes a `SRC File.java:N-M` reference has no internal whitespace, but this file (and, per the brief's recipe notes, others) routinely writes multi-range citations as `N, M-K` with a space after the comma - the file's own established style, also used in `SCHEMA_V2.md`'s own example. That silently truncates the citation and then crashes `snippet()` on the dangling empty segment. Reproduce a tool crash on one method before assuming the method itself is unreadable; a small local patched copy (kept inside the app folder, not in `tools/`) let the rest of the sample be read normally.
- **`scan_unreachable.py --all --callers` earns its keep even when a UNREACHABLE cluster looks obviously dead.** The `Home$CallLogObserver` cluster (closed because `READ_CALL_LOG` is commented out of the manifest) still has two bytecode callers from very-much-reachable methods (`Home.initQuickCenter`, `Home.onRequestPermissionsResult`); the existing reason text already named and explained both, but the check is cheap and is exactly the kind of thing that is easy to skip when a cluster "obviously" looks dead from the manifest alone.
- **Reading a whole method once, instead of only the cited sub-ranges, is worth the extra few lines.** Every other citation this session (framework and app) matched exactly what its prose claimed; the one real error was found specifically because the fix required seeing code *outside* any single citation's range (the position of `System.exit(1)` relative to the try/catch two statements above it).
