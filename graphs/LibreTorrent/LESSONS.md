# LibreTorrent logs — lessons (B6 / D7 / D5 findings only)

- UNRESOLVED means pathless, not edgeless: B6's route-2 disclosure records that the graph's BFS skips non-standard dispatches such as alarm delivery, so the 86 UNRESOLVED methods lack a graph path, not necessarily executability — never read "no path" as "cannot run" (B6 route table, Findings).
- Finalize-from-constructor is not a route: no program code calls `finalize` from a constructor, and the graph's own trigger admits GC finalization, which is nondeterministic and not guaranteed in one execution — a drawn step resting on GC is FALSE, not merely slow (B6 route 3, FeedDao_Impl$11.finalize, decisive step 20, edge E8756175a).
- Dialog-mode conflation mixes prefixes that cannot coexist: a route that launches a dialog in one mode (FILE_CHOOSER_MODE, ADD mode) and continues in another mode's handlers (SAVE_FILE_MODE, EDIT mode) is not one real execution, even when every step is sound in isolation (B6 routes 4 and 7, PathResolver.join and FeedDao_Impl$1.bind).
- A SAF seed is necessarily file:// on a fresh install: the in-app picker returns Uri.fromFile results only, the default save path is file://, and a whole-app grep for the system document-picker actions returns only comment hits — so any route needing a content:// prefix must say where that prefix comes from outside the app, or it is not drawable (B6 routes 17 and 19, SafFileSystem.getParentDirUri and safRoot).
- Check-8 --all 0 is 0 by construction: the tool appends to its quiet list only when --all is NOT passed, so the substantive check-8 figure is the default split (606 with other mentions / 158 with none) and the --callers figure (33), never the --all 0 (D7 report, check 8a).
- Check-4 "checked" excludes file-not-found lines, so bad is not a subset of checked: a `file not found` line lands in bad WITHOUT incrementing checked, which is why 141 bad sits alongside 1673 checked rather than inside it — do not report 141/1673 as a rate (D7 report, check 4; D5 Class A 134 + Class B 7 = 141).
