What was reviewed by hand (class level, from method names, the manifest, the Hilt-generated classes and the baseline hit counts):

- **What the baseline reached.** The 1-hour runs got past the first-run setup and showed the vault list (`MainActivity`, `EntryListView`, `FabMenuHelper`, `Preferences`, the settings fragments, `AboutActivity`, `GroupManagerActivity`, parts of the import / export screens, `ScannerActivity`), but **the vault stayed empty: `EntryAdapter.onBindViewHolder` never ran**, so nothing that needs an entry (row binding, copy / edit / delete / group actions, the action mode, `TransferEntriesActivity`) was exercised. Only 751 of the 2,995 methods ran.
- **Gates added (edges into these classes, when the baseline never ran the target):** `needs_state` for `AuthActivity` (a password-protected, locked vault: the baseline vault opened without an unlock screen), for the Glide request classes (an entry with a custom icon or icon pack; the baseline entries used the default letter icon), and for the importers of the other authenticator apps (`AndOtpImporter`, `AuthyImporter`, `FreeOtpImporter`, `GoogleAuthImporter`, `StratumImporter`, `TwoFASImporter`, ... : a backup file of that app, none among the baseline fixtures); `env` for the quick-settings tile classes (`LaunchAppTileService`, `LaunchScannerTileService`, `QsTileRefreshReceiver`) and for the biometric classes (`BiometricSlot*`, `BiometricsHelper`: the emulators had no enrolled biometrics). The Android backup agent (`AegisBackupAgent`, declared as `android:backupAgent`) is entered from `S_ENTRY` through an `env` edge: the system Backup Manager creates it.
- **Branch gates read from the source at the frontier (`CFG['EDGES']`):** `MainActivity.handleIncomingIntent` -> `startEditEntryActivityForNew`, `startDecodeQrCodeImages`, `GoogleAuthInfo.parseUri` need an incoming intent from another app (otpauth:// VIEW, SEND, SEND_MULTIPLE): `env`; `ImportEntriesActivity.lambda$startImportApp$5` -> `readFromApp` / `processImporterState` need a root shell and the other authenticator app installed (`ImportEntriesActivity.java:149` shows a root error and finishes otherwise): `env`; `startGoogleAuthenticatorStyleExport` -> `TransferEntriesActivity` needs at least one entry (a toast otherwise): `needs_state`; `MainActivity.onStart` -> `startAuthActivity` needs a locked vault (`!isVaultLoaded()`): `needs_state`; the save button of `ImportEntriesActivity` needs a finished import: `needs_state`.
- **Hilt / Dagger.** `DaggerAegisApplication_HiltComponents_*`, `Hilt_*` base classes and `AppDatabase_Impl` (Room) are in the method universe; they are linked through the class-literal, `@Inject` and generated-implementation rules (see "Method"). `GlideApp`, `GeneratedAppGlideModuleImpl`, `GlideOptions`, `GlideRequest(s)` are the Glide annotation-processor classes (loaded by name when Glide initialises).
- **Dead code** is mostly generated or library code the app never calls: `GlideApp` (all 15 methods), the unused overloads of the protobuf classes `GoogleAuthProtos$MigrationPayload*` (`parseFrom`, `parseDelimitedFrom`, `newBuilder` variants), `TextDrawable$Builder`, `TrustedIntents` and `ApkSignaturePin` (trusted-intents library), `NotificationService`, some `Dialogs` and `Preferences` helpers.
- **Not gated but never run (the target list):** `EditEntryActivity` (the add / edit entry form, reached from the FAB menu), the `MainActivity` search / group-filter / import-scan helpers, `Dialogs` lambdas for backup versioning and checkboxes, `BackupsPreferencesFragment`, the export code of `VaultRepository`, the security preferences. All are one or a few taps from the vault list.
