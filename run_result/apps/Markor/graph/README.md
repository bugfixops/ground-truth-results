# Markor 2.16.1 (flavorAtest debug build, net.gsantner.markor_test): method-level trigger graph (schema 2)

How every method of **Markor** is triggered, in the standard configuration: the instrumented debug build (`gsantner/markor@v2.16.1`, commit `c538c1d38ba4`, APK sha256 `06ceb408...`), an API 27 emulator, permissions and fixtures as in `final_java_only`. Labels follow `handoff/SCHEMA_V2.md`: REACHABLE or UNREACHABLE, ENV and STATE gates, edge classes (explicit, standard, non-standard), and how each label was confirmed.

## What is in this folder

| File | What it is |
|---|---|
| `markor_trigger_graph.json` | pages, methods, `verdict`, `labels` (per-method fields), `edges` (with `edge_class`, `env_kinds`, `state_kinds`, stable ids), `paths` (verified paths only), `verification` (counts) |
| `methods.csv` | one row per method: verdict, UNREACHABLE reason, ENV and STATE kinds and texts, edge classes on the best route, whether an explicit/standard-only route exists, how the label was confirmed, path status, the derived best route (`shortest_path`, `route_edge_ids`), and the full JVM class and descriptor (`jvm_class`, `jvm_descriptor`; the `method` key adds a package prefix only where simple class names clash) |
| `../verification.csv` | the audit log: one row per label, edge or path that was checked, with result, how, and where (file:line) |
| `sanity_check.csv` | tool coverage (Monkey / APE, API 27) next to the labels; a one-way check only, it never sets a label |
| `markor_trigger_graph.html`, `build_report.txt` | the viewer and the validation report |

## How the checked paths were chosen

- The 30 path rows are the final draw of `tools/verify_sample.py Markor 30` (seed 20261025). make_verification.py runs that draw itself at each rebuild, so the path rows follow the draw. The draw has six strata with these counts: NONSTD 4, INFERRED 4, STATE 3, ENV 6, LONG 6 (12 or more steps), PLAIN 7. Inside a stratum, the method that adds the most edges not yet covered comes first.
- The logged path rows equal the final draw: 30 of 30, as a set and in the same order. The draw is identical on re-draw (checked after the last rebuild, 2026-10-27).
- Result for the 30 path rows: 13 correct, 17 fixed, 0 wrong (17/30 = 56.7%). A fixed route is one whose built edges lacked a condition the code requires (guard, receiver check, listener guard, or cold-start step); each path row's note says which.
